# 04. Baseline-8 필수 요구 명세 및 추적 매트릭스

발주자가 지정한 **무조건 구현 대상** 8종이다. 이 문서가 최종 인수의 기준이며, 작업계획의 다른 유닛이 전부 닫혀도 §3의 E2E 시나리오가 통과하지 않으면 인수되지 않는다.

## 1. 요구 원문과 해석

### R1. 문서저장(AWS) + 매터코드/고객별 문서목록 + 열기/편집
문서는 AWS 클라우드(S3)에 저장되고, 사용자는 매터코드 또는 고객 기준으로 관련 문서 목록을 확인하고 문서를 열람·편집할 수 있어야 한다.
- 해석: /files(전체 보관함)와 매터 상세 문서함은 기존 구현. **고객 축**은 /files의 clientId 필터 + 고객명 컬럼 + /clients 상세의 문서 탭으로 충족(B15).

### R2. 문서 메타데이터: 이름, author, 편집순 정렬(초단위), matter code, 고객
- 해석: 이름·author(created_by)·matter code는 기존 저장. 편집순 정렬은 `updated_desc` 서버 정렬(timestamptz, 마이크로초 정밀)로 기존 충족. 부족분은 **최종 편집자(updated_by) 저장·노출과 고객명 컬럼**(B15).

### R3. 문서의 version 및 sub-version 관리
- 해석: 기존 구현으로 충족 — 공식 버전(document_versions, vN) + 검토본 서브버전(document_subversions, vN.M) + 리뷰게이트 + 승격(promote) + 버전 표준 라벨(v0.1 내부초안/v1.0 고객송부/Final/Execution Copy/Clean·Markup, 0119). B6가 잠금 운영성 보강.

### R4. copy본과 reference본
reference본 = 용량 작고 편집 시 vault DB에 곧바로 반영. copy본 = 다운로드→로컬 수정→별도 업로드로 반영. 한 명이 reference로 작업 중이면 두 번째 접근자는 동시 편집이 차단되고 "copy본으로 작업할까요?" 질문 후 승인 시 copy본이 열린다.
- **합의된 정의(잠금 기준 — 킥오프 결정 D-07에서 발주자 서면 확인)**: **reference본 = 체크아웃 잠금을 보유한 편집 세션에서의 작업** — 웹 편집기(vault_text) 또는 데스크톱 브리지(B12)로, 저장 즉시 vault에 검토본으로 반영된다. **copy본 = 잠금 없이 받은 작업사본** — 감사 다운로드(purpose=working_copy)로 받아 로컬 수정 후, 잠금 해제 뒤 새 버전 업로드로 반영한다. 즉 reference/copy는 파일 포맷이 아니라 "잠금을 쥐고 작업하는가"의 구분이다(DOCX도 B12 편집 세션이면 reference 작업).
- 동시 편집 차단은 체크아웃 잠금으로 기존 구현. **부족분은 잠금 충돌 시 copy 분기 프롬프트 UX**(B16): 잠금 소유자 표시 + [작업사본 다운로드/잠금 해제 요청/취소] 선택지 + 서버 결정 사본 파일명 + 감사 이벤트 + 잠금 활성 중 새 버전 업로드 차단 정책(체크인 후 업로드).

### R5. 더블클릭 → MS Word로 reference본 열림 → 편집 → 저장 시 버전업/서브버전업 선택
- 해석: B12(데스크톱 편집 브리지)로 "편집 클릭 1회 → 로컬 Word/한컴 자동 실행 → 저장 감지 → 자동 검토본 저장 → 종료 시 체크인/취소"를 구현(더블클릭과 기능 등가로 발주자 합의). **버전업/서브버전업 선택은 체크인 시점 다이얼로그**(B17): [검토본 유지 vN.M] / [공식 버전 발행 vN+1 + 버전 라벨 선택]. 9인 완화로 리뷰어 미지정 문서는 즉시발행(self-promote) 허용을 테넌트 정책 플래그로 제공.
- 명시적 범위 외: WOPI/Office Online 브라우저 편집, co-authoring(동시 편집). ADR-018(B12에서 신규 작성 예정인 평가 문서)에서 go/no-go 평가만 수행.

### R6. 본문 + 매터코드, 고객 등 다양한 정보로 검색
- 해석: 기존 구현으로 충족 — 본문/제목 FTS(한국어 n-gram 0109 적용) + matterId/clientId/matterCode/문서유형/비밀등급/privilege/legal hold/날짜/버전상태 필터 + facet + 권한내 검색. D1~D6이 품질 보강(실임베딩 의미검색, 1MB 절단 해소 등).

### R7. Outlook add-in: 발송 시 e-filing 질문 → 저장 선택 시 매터코드 선택 저장
- 해석: 발송 시점 Smart Alerts(OnMessageSend, SoftBlock) 프롬프트는 기존 구현. compose 태스크페인의 매터 선택+"전송+보관" 요청 기록도 기존 구현. **부족분**(C16): send_and_file 요청의 실제 이행(발송 후 Sent Items에서 Graph로 원문 취득→저장→매터 타임라인 표시), Smart Alerts 프롬프트→태스크페인 연계, 매터코드 자유검색 picker(추천 실패 시 폴백). 수신 메일 파일링은 C1~C7로 완결.

### R8. 각 버전별 음절단위 redline PDF 생성 (Contract Desk 이식)
- 해석: Contract Desk 앱(v0.14.24)의 검증된 문자(음절)단위 Myers diff 엔진을 `packages/redline`으로 이식(B18)하고, 버전쌍 선택→redline PDF 생성(요약 페이지+본문 redline+변경노트)→권한·감사 통제 하 열람·다운로드를 vault에 내장(B19). 서식보존 트랙체인지 DOCX는 조건부 2단계(B20). 상세는 `05_contract-desk-redline-port.md`.

## 2. 요구 → 유닛 추적 매트릭스

| 요구 | 이미 충족(기존 코드) | 필요 유닛 (H1) | 필요 유닛 (H2) | 필요 유닛 (H3) |
|---|---|---|---|---|
| R1 | S3 저장, 매터별 문서함, /files, 편집 라이프사이클 | **B15** | B12(Word 열기 경험) | — |
| R2 | author·matter code 저장, updated_desc 정렬(㎲ 정밀) | **B15**(updated_by·고객 컬럼) | D5(검색 카드 보강) | — |
| R3 | 버전+서브버전+리뷰게이트+승격+라벨(0119) | B6(잠금 운영성) | — | — |
| R4 | vault_text/binary_roundtrip 이원, 체크아웃 잠금 | **B16**, B6 | — | — |
| R5 | 체크아웃→저장→체크인→승격 흐름 | B6 | **B12**, **B17** | — |
| R6 | FTS+메타 필터+facet+권한내 검색, 한국어 n-gram | D1~D4(품질) | D5, D6 | — |
| R7 | Smart Alerts 프롬프트, compose 매터 선택+기록 | C1~C7(수신 파일링 완결) | **C16**, C13, C15 | C14(DLP 1종) |
| R8 | (없음 — Contract Desk 앱에 별도 존재) | — | **B18**, **B19** | B20(조건부) |

**굵은 글씨**가 해당 요구의 결정적(critical-path) 유닛이다. Baseline-8만 최우선으로 닫는 최단 경로(하드 의존 포함):
`B15 → B6 → B16`(잠금 운영성 선행) → `C1~C7`(수신) → `C16`(발신) → `B12 → B17`(Word 편집, B6 의존) → `B18 → B3 → B19`(redline, 워터마크 선행). 이 경로로 8종 전부 E2E 통과 가능하다.

## 3. E2E 인수 시나리오 (최종 인수 기준 — 발주자 직접 수행)

전건 통과 + 서명으로 인수 완료. **수행 시점**: 프로젝트 완료 판정 직전, DMS 표면에 영향을 주는 마지막 머지 이후 4주 이내(중간 마일스톤 수행 기록으로 갈음 불가).

**수행 환경(확정)**: AT-6·AT-7은 실 M365 테넌트 필수. AT-5·AT-8은 프로덕션(또는 실데이터 동급 규모를 적재한 프로덕션 동급 사양 스테이징). AT-1~AT-4는 스테이징 허용.

**재시험 규칙**: 실패한 AT는 수정 배포 후 전체 단계를 처음부터 재수행한다. 수정이 공유 표면(편집 라이프사이클·권한·검색)에 영향을 주면 영향 받는 다른 AT도 동반 재수행하고 회귀 스위트(tests/integration) green을 함께 확인한다. 한 단계라도 실패하면 해당 AT 전체 실패.

### 3.0 사전 준비물 체크리스트 (수행 전 전부 구비 — 발주자·개발팀 공동)

- **계정**: 변호사 계정 2개(권한 대조용 — AT-3·5·8), Outlook 파일럿 계정 1개(AT-6·7 — SEND_FILE 허용 링 소속, D-04 결정 반영), 검수 보조 1인.
- **데이터**: 제한 매터(access_scope=restricted) + 그 안의 문서 1건 + 비권한 계정(AT-5.4·AT-8.4용), vault_text 웹편집용 텍스트 문서 1건(AT-3.5), 첨부 1개 이상 포함 외부 수신 메일(AT-6), 익명화 100페이지급 계약서 v1/v2 쌍(AT-8).
- **환경**: 데스크톱 앱 설치 PC + MS Word 라이선스(AT-4), M365 테넌트 add-in 배포 완료(C7/C15), AT-5 수행 전 색인 완료 기준 충족(업로드 후 10분 경과 또는 색인 상태 확인).
- **정책**: AT-4 대상 문서는 리뷰어 미지정 + self-promote 플래그 on(D-03이 off로 결정된 경우 AT-4.3을 리뷰어 승인 경유 절차로 대체 수행함을 병기).

### AT-1 (R1·R2)
1. 신규 매터 생성(고객 지정) → DOCX 계약서 업로드. 2. /files에서 해당 고객으로 필터 → 방금 문서가 목록에 보이고 행에 고객명·작성자·최종 편집시각 표시. **2b. 해당 매터 상세 화면의 문서함에서도 같은 문서가 표시됨을 확인(매터코드 축).** 3. 다른 사용자가 해당 문서를 편집·체크인 → 목록 재정렬(최근 편집순) 및 최종 편집자가 그 사용자로 갱신 확인. **3b. 같은 분(minute) 내에 서로 다른 문서 2건을 순차 체크인한 뒤, /files 최근 편집순에서 두 문서의 순서가 체크인 순서와 일치함을 확인(초단위 정밀도).** 4. 문서 미리보기 렌더 성공 + 편집 시작 시 체크아웃 잠금 생성 확인.

### AT-2 (R3)
1. AT-1 문서를 편집 → 저장 2회(검토본 vN.1, vN.2 생성 확인) → 체크인 → 공식 발행. 2. 버전 목록에 vN+1과 검토본 이력이 함께 표시. 3. vN+1에 버전 라벨(예: 고객송부본) 부여 → 배지 표시 확인.

### AT-3 (R4)
1. 사용자 A가 DOCX 문서 편집 시작(체크아웃). 2. 사용자 B가 동일 문서 편집 시도 → "A님이 편집 중"(소유자 표시명·만료예정) 안내와 함께 [작업사본으로 열기] 프롬프트 표시. 3. B가 승인 → `{원제}_copy_B_{일시}` 파일 다운로드, 문서 감사 타임라인에 사본 다운로드 이벤트 표시. 4. **A 잠금 활성 중** B가 새 버전 업로드 시도 → 잠금 안내와 함께 차단됨을 확인. **A가 체크인(잠금 해제)한 후** B의 "새 버전으로 업로드"가 성공하고 버전 체인이 순서대로 이어짐을 확인. 5. **별도의 vault_text(웹 편집) 텍스트 문서**에서: 편집 세션 중 저장 즉시 검토본(vN.M)이 DB에 반영됨을 확인(reference본 동작).

### AT-4 (R5)
1. 데스크톱 앱에서 DOCX 문서의 [편집] 클릭 → 로컬 MS Word가 자동 실행되어 문서 열림. 2. Word에서 수정·저장(Ctrl+S) → **저장 후 90초 이내** vault에 검토본 자동 기록. 3. Word 종료 → 체크인 다이얼로그에서 [공식 버전으로 발행 + 라벨 선택] → 버전 목록에 vN+1 반영(사전 준비물 §3.0의 정책 전제 참조). 4. 같은 문서를 [검토본 유지]로 닫는 경로도 확인. 5. HWP 문서 동일 절차 1회(킥오프 결정 D-09에서 최종 인수 포함 여부 확정 — 포함 시 수행).

### AT-5 (R6)
1. 계약서 본문에만 존재하는 한국어 구절로 검색 → 해당 문서가 **상위 3건 이내** 표시. 2. 매터코드로 검색 → 해당 매터 문서들. 3. 고객 facet으로 축소 → 해당 고객 문서만. 4. 권한 없는 제한 매터 문서는 결과에 나타나지 않음(계정 2개 대조 — §3.0 준비물의 제한 매터 사용).

### AT-6 (R7 수신)
1. Outlook에서 **첨부 1개 이상 포함** 외부 수신 메일 선택 → add-in 태스크페인 → 추천 매터 선택(추천 없으면 자유검색) → 파일링. 2. 1분 내 해당 매터 타임라인에 메일+첨부(문서로 분리) 표시. 3. 동일 메일 재파일링 시 중복 차단 확인.

### AT-7 (R7 발신)
1. Outlook에서 외부 수신자에게 새 메일 작성 → 보내기 → "파일링 후 발송" SoftBlock 프롬프트 표시. 2. 태스크페인에서 매터코드 검색·선택 → [전송+보관] → 메일 정상 발송. 3. 1분 내 해당 매터 타임라인에 발신 메일 표시. 4. 프롬프트에서 무시하고 발송하는 경로도 동작(차단이 아닌 권고).

### AT-8 (R8)
