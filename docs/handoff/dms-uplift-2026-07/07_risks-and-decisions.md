## 2. 결정 사항

### 2.1 킥오프 확정 결정 (발주자가 킥오프에서 답한다 — 4건 + 신설 3건)

| # | 결정 | 선택지 | 권고 | 발주자 관점 효과 |
|---|---|---|---|---|
| D-01 | 한국어 FTS 방식 | pg_bigm(단순)/textsearch_ko·mecab(정확) vs OpenSearch 도입 | **Postgres 내 해결(D1 명세대로)** — 성능 임계 시(D9 트리거) 재평가 | 권고안은 추가 서버 없이 현행 인프라로 한국어 본문 검색 정확도를 확보. OpenSearch는 대규모 성능 여력 대신 운영비·관리 부담 증가 |
| D-02 | 임베딩 모델·서빙 | bge-m3 로컬(전용 컨테이너) vs 외부 API | **bge-m3 로컬**(D2 명세대로) | 권고안은 비닉특권 문서 원문이 외부로 전송되지 않음(privilege 보호). 외부 API는 품질 향상 여지 대신 원문 외부 전송 발생 |
| D-03 | self-promote 정책 기본값 | 리뷰어 미지정 문서의 체크인 시 즉시발행 허용 여부 | **허용(on)** — 테넌트 플래그로 언제든 게이트 복원(B17) | on이면 혼자 작업하는 문서를 검토 절차 없이 바로 공식 버전으로 발행 가능(9인 내부용 취지). off면 항상 검토자 승인 필요 |
| D-05 | 데스크톱 브리지 임시파일 정책 | 편집 종료 즉시 삭제 vs 세션 캐시 유지 | **즉시 삭제 + 암호화 임시 디렉토리**(B12 acceptance 반영) | 권고안은 PC 분실·공유 시 문서 사본이 남지 않음. 캐시 유지는 재열기 속도 대신 유출면 증가 |
| D-07 | reference/copy 정의 및 인수 환경 | `04` §1 R4의 잠금 기준 재정의 + §3 수행 환경 확정안 승인 | **승인 권고** | R4·R5 인수 시나리오(AT-3·AT-4)의 판정 기준이 이 정의에 걸려 있음 — 서명 전 반드시 확인 |
| D-08 | Contract Desk 원본 git 미제공 시 폴백 | 스냅샷(v0.14.24) 기준 이식 승인 여부 | 킥오프 후 2주 내 git 접근 제공, 불가 시 **스냅샷 기준 승인** | 스냅샷 기준 이식 시 그 이후 Contract Desk 개선분은 반영되지 않음 |
| D-09 | HWP 편집의 최종 인수(AT-4) 포함 여부 | 포함(AT-4에 HWP 절차 추가) vs Word만 | 한국 로펌 실무상 **포함 권고** — 단 한컴오피스 설치 PC 필요 | 포함하지 않으면 HWP 문서는 다운로드-업로드 방식으로만 편집 |

## 3. 진행 중 재평가 트리거 (조건부 유닛)

- **D9(검색 성능 물질화)**: /search p95 > 3초가 1주 이상 지속되거나 문서 30만 건 초과 시 착수.
- **B20(서식보존 redline)**: B19 실사용 4주 후 발주자가 서식보존 필요를 서면 확인 시 착수.
- **H14(Microsoft OIDC)**: MFA(H1) 운영 후 로그인 불편 피드백이 있을 때만.

## 4. 에스컬레이션 규칙 (승인 권한 이원화)

- **발주자 서면 승인 필수** (개발팀 리드 단독 승인 불가): Baseline-8 요구 해석·AT-1~AT-8 시나리오·프로젝트 DoD·완화 정책(01 §4)·조건부 유닛 목록에 영향을 주는 **모든** 명세 변경. acceptance test의 대체·완화 포함.
- **리드 승인으로 처리 가능**: 그 외 유닛 내부 구현 편차(앵커 소멸, 선행 유닛에서 이미 구현됨 발견 등) — 라이브 작업계획에 편차를 기록하고 리드 승인 후 진행.
- 판단이 애매하면 발주자 승인 경로로 올린다.
