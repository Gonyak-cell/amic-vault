# 85. Human Operations Playbook — 사람이 할 일

버전: 1.0 | 2026-06-11 | 독자: PO/관리자(사용자 본인), 검토 변호사

Codex는 PACK 단위로 구현·검증·PR 생성까지 수행하고, 운영자가 명시적으로 지시한 PR은 병합할 수 있다. 이 문서는 사람의 결정과 Codex의 기술 검증이 필요한 시점과 내용을 정의한다.

## 2. 상시 — PACK 사이클마다 (R0~R3 동안 25회)

| # | 할 일 | 규칙 | 소요 |
|---|---|---|---|
| H-05 | **PR 기술 검증** | PACK 완료(PR 생성) 시 Codex가 §2-A 체크리스트를 수행하고 검증 결과를 PR에 남긴다. 운영자가 병합을 지시하면 최신 main·CI·diff를 다시 확인한 뒤 병합한다 | 검증 결과 확인 |
| H-06 | **검증 내용** | ① PR 본문의 검증 명령 결과(전부 green) ② Risk=C TUW의 negative test가 실제로 차단을 증명 ③ `Files NOT to modify` 위반 여부(diff 범위) ④ 테스트 약화·skip 흔적을 확인하고 **비전문가용 한국어 요약**으로 보고 | (H-05에 포함) |
| H-07 | **BLOCKED escalation 처리** | Codex가 중단하면 PR에 `BLOCKED` 라벨+사유가 남는다. Codex는 기술적 원인을 확인하고, 비용·법률·제품 방향 등 운영자 결정이 필요한 사항만 평어로 질문한다 | 필요 시 결정 |
| H-08 | **다음 PACK 투입** | 병합 결과와 원격 main 재확인 후 Codex에 **"다음 PACK 진행"** 입력 — 순번 결정·선행 확인은 Codex가 AGENTS.md §3.0 규약으로 스스로 수행 | 1분 |

### §2-A. 기술 검증 체크리스트 (Risk=C PACK 머지 전 필수)

운영 결정(2026-09-25): Codex가 체크리스트를 직접 수행하고 검증 결과를 PR에 남긴다. 외부 독립 리뷰는 자동 병합 조건이 아니며, 운영자가 특정 PR에 요청한 경우에만 별도로 수행한다. 개발 기간(R0~R3)에는 실데이터를 반입하지 않는다. 실제 고객 데이터 투입(운영 배포) 전 사람(보안 전문가) 검토는 별도 운영 판단으로 남는다.

- [ ] **diff 전체를 직접 읽었다** — 특히 `permission/`, `audit/`, `ethical-wall/`, storage 경로의 변경
- [ ] **검증 명령 출력을 확인했다** — negative test(비인가 차단)가 실제 실행·통과했고, 테스트 개수가 직전 대비 줄지 않았다
- [ ] **Files NOT to modify 위반이 없다** — diff 파일 목록을 해당 TUW 명세와 대조
- [ ] **테스트 약화가 없다** — `.skip` / `xit` / `it.todo` / expected 완화 흔적 grep
- [ ] **C TUW의 Verification 항목마다 대응 테스트가 존재한다** — 40~43번 명세의 AND 목록과 1:1 대조
- [ ] **검증 결과를 기록했다** — PR 본문에 체크리스트 결과와 테스트 근거를 남긴 뒤 병합

## 3. Release Gate마다 — R0~R3에서 4회 (통과 전 다음 release 착수 금지)

| Gate | 사람이 승인할 것 | 근거 문서 |
|---|---|---|
| **R0 Gate** | Foundation 체크리스트(G0-01~30) + **ADR-001~012 승인**(Decision Ledger 등재) | 50번 §2, 01번 |
| **R1 Gate** | 권한 매트릭스 하네스 100%·audit coverage·fail-closed 증명 + **Permission Model Freeze(ADR-013) 승인** — 이후 권한 인터페이스 변경은 사람 승인 필요 | 50번, 41번 §4 |
| **R2 Gate** | hash/원본 불변·hold 차단·storage 격리 체크리스트(G2-1~15) + **Q-003 HWPX 범위 결과 확인** | 50번, 42번 |
| **R3 Gate** | **metadata leakage 0건·사후 필터링 0건 확인**(불통과 사유 명문화됨) + **ADR-006 OpenSearch 전환 여부 결정**(KOREAN-EVAL-002 보고서 기반) + 평가셋 v0 적재 확인 | 50번, 43번 §4 |

Gate 점검은 Codex가 기술 근거를 확인하고 비전문가용 요약으로 보고한다. 운영자는 요약을 보고 "다음 release 진행"을 지시할 수 있다.

## 6. 요약 — 사람의 시간 예산 (R0~R3 기준)

- 착수 셋업: **약 1시간** (H-01~04)
- PACK 기술 검증: Codex가 §2-A를 수행하고 PR에 결과를 남긴다
- Gate 4회: **약 2일**
- 변호사 입력: 평가셋 1~2일 + taxonomy 1시간
- 예측 불가 항목: BLOCKED escalation (설계상 Codex가 추측하지 않고 멈추므로, 응답 속도가 전체 일정을 좌우한다)

**원칙: 기술 검증 지점은 유지한다.** Risk=C 머지·Gate 통과·Freeze에서 권한·격리·감사와 검증 증거를 확인한다. 운영자가 병합을 명시적으로 지시하면 Codex가 병합과 원격 main 재확인을 수행할 수 있다. 법률 값 입력(보존기간·평가셋 선별)과 비용 결정은 사람 몫으로 남는다.
