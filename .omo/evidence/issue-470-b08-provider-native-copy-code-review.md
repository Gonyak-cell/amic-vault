## MEDIUM

### M1. The service remains an oversized security-critical module

`amic-os-vault-document-copy.service.ts` is 762 physical lines and 725 nonblank/noncomment lines. It combines boundary response projection, cursor handling, repository SQL, source authorization, quarantine storage, the state machine, and publication. This violates both loaded skill perspectives' 250-line ceiling and makes future lifecycle changes harder to reason about.

This is not raised to HIGH because the previously defective boundaries now have focused and real-PostgreSQL regression coverage, and no remaining correctness failure was demonstrated. A follow-up should split repository/state transitions, snapshot storage verification, and orchestration/publication while preserving the public service contract.

### M2. The typed missing-object branch does not match the current S3 `get` error

`complete()` treats `StorageExactVersionMissingError` as a permanent missing snapshot (`amic-os-vault-document-copy.service.ts:362-381`), but the quarantine read uses `StorageService.getByStorageUri()`, whose S3 adapter reports a 404 as generic `StorageUnavailableError('storage object missing')` (`s3-storage.adapter.ts:203-211`). Consequently, a physically missing quarantine object remains `prepared` and retryable rather than becoming `blocked/snapshot_unavailable`. The tests cover corrupt bytes and a temporary storage outage, but do not cover the actual S3 404 type.

This does not break normal prepare/read/commit: prepare publishes the row as `retained` in the same transaction that serializes the object write, and all retained reads fail closed if bytes are absent. It is a recovery-state classification gap. Align the adapter/service error taxonomy and add the missing-object case when the storage error contract is next changed.

### M3. The PostgreSQL concurrency test contains an unnecessary timing wait

`tests/integration/amic-os-vault-document-copy.spec.ts:309-318` waits 50 ms after launching the second prepare. The final assertions that both requests complete, only one quarantine write occurred, and the exact bytes are readable already establish the serialized outcome, so the timer adds timing dependence without adding proof. Remove the wait or replace it with an explicit second-request arrival signal in a follow-up.
